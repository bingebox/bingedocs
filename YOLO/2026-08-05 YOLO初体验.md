# YOLO初体验

## 1. 前言

### YOLO是什么？

YOLO（You Only Look Once）是由Joseph Redmon等人提出的**实时目标检测**算法框架。与传统的两阶段检测器（如R-CNN系列需要先候选区域再生成边界框）不同，YOLO将目标检测视为**单一的回归问题**，直接在图像上一次性预测边界框和类别概率，因此得名"只看一眼"。

### 发展历程

| 版本 | 发布时间 | 核心改进 |
|------|----------|----------|
| YOLOv1 | 2016 | 首次提出端到端单阶段检测框架 |
| YOLOv2/YOLO9000 | 2017 | 引入锚框、批归一化、高分辨率分类器，支持9000类 |
| YOLOv3 | 2018 | 多尺度预测、残差网络、Focal Loss |
| YOLOv4 | 2020 | 集合多种SOTA技巧（SAM、CASPP等） |
| YOLOv5 | 2020 | Ultralytics重构，易用性大幅提升，社区繁荣 |
| YOLOv6 | 2022 | 美团主导，面向工业部署优化 |
| YOLOv7 | 2022 | 扩展模型和特征融合，精度再突破 |
| YOLOv8 | 2023 | Anchor-Free、解耦头、新的损失函数 |
| YOLO11 | 2024.09 | 更少参数更高精度、改进的Backbone和Neck |
| YOLO26 | 2026 | **原生端到端NMS-Free推理**、DFL-Free回归、MuSGD优化器、任务专用Head |

> 截至2026年，Ultralytics官方主推 **YOLO26** 和 **YOLO11** 两个系列，均支持生产环境部署。

### 为什么选择YOLO？

- **实时性**：在GPU上可达数百FPS，满足实时视频流处理需求
- **精度高**：在COCO等基准数据集上SOTA表现
- **生态完善**：Ultralytics提供Python API + CLI + 云平台，社区活跃
- **部署灵活**：支持导出ONNX/TensorRT/OpenVINO，可部署于边缘设备、移动端、云端

## 2. YOLO功能包括哪些

Ultralytics YOLO26是一个**统一框架**，支持以下计算机视觉任务：

### 2.1 目标检测（Detection）
在图像中识别物体并绘制边界框，是YOLO最核心的任务。适用于安防监控、自动驾驶、工业质检等。

### 2.2 实例分割（Segmentation）
在检测基础上，为每个目标生成像素级掩码（mask）。适用于医学影像、农业分析、制造质检。

### 2.3 语义分割（Semantic Segmentation）
对图像中每个像素赋予类别标签，但不区分同类的不同实例。适用于自动驾驶场景理解、地物分类。

### 2.4 深度估计（Depth Estimation）
从单张RGB图像预测像素级深度图（米制单位）。适用于3D重建、机器人导航、AR/VR。

### 2.5 图像分类（Classification）
将整张图像归类为预定义类别。适用于电商商品分类、内容审核、 wildlife监测。

### 2.6 姿态估计（Pose Estimation）
检测图像中的人体/动物关键点（关节、面部特征等）。适用于运动分析、健身应用、人机交互。

### 2.7 旋转目标检测（OBB - Oriented Bounding Box）
在边界框基础上增加旋转角度，更适合航空影像、卫星图像中任意方向的物体。

### 2.8 多目标跟踪（Tracking）
在视频帧中持续跟踪多个目标并分配唯一ID，内置BoT-SORT和ByteTrack算法。

### 2.9 开放词汇检测（YOLOE-26）
支持基于**文本提示**、**视觉提示**或**免提示模式**的动态类别检测，适应训练时未见过的类别。

### 任务与模式矩阵

每个任务都支持以下**操作模式**：

| 模式 | 说明 |
|------|------|
| `train` | 在自定义数据集上训练模型 |
| `val` | 验证模型在测试集上的性能 |
| `predict` | 对新图像/视频进行推理 |
| `export` | 导出为ONNX/TensorRT/OpenVINO等格式 |
| `track` | 视频多目标跟踪 |
| `benchmark` | 模型性能基准测试 |

## 3. 怎么搭建和使用 YOLO？

### 3.1 安装

```bash
# 通过 pip 安装（推荐）
pip install ultralytics

# 验证安装
python -c "from ultralytics import YOLO; print('YOLO OK')"
```

可选方案：
- **Conda**: `conda install -c conda-forge ultralytics`
- **Docker**: `docker pull ultralytics/ultralytics`
- **源码安装**: `git clone https://github.com/ultralytics/ultralytics && cd ultralytics && pip install -e .`

### 3.2 推理（预测）

**Python API：**
```python
from ultralytics import YOLO

# 加载预训练模型
model = YOLO("yolo26n.pt")

# 对单张图片推理
results = model("image.jpg")

# 可视化结果
results[0].show()

# 保存结果
results[0].save(save_dir="results/")
```

**命令行（CLI）：**
```bash
# 单张图片推理
yolo predict model=yolo26n.pt source=image.jpg

# 视频推理
yolo predict model=yolo26n.pt source=video.mp4

# 摄像头实时推理
yolo predict model=yolo26n.pt source=0

# 文件夹批量推理
yolo predict model=yolo26n.pt source=./images/
```

### 3.3 多目标跟踪

```python
# Python API
results = model.track(source="video.mp4", show=True)

# CLI
yolo track model=yolo26n.pt source=video.mp4
```

支持跟踪算法：BoT-SORT、ByteTrack。

### 3.4 模型导出（部署）

```python
# 导出为ONNX
model.export(format="onnx")

# 导出为TensorRT（需要GPU）
model.export(format="engine", device=0)

# 导出为OpenVINO
model.export(format="openvino")

# 导出为TorchScript
model.export(format="torchscript")
```

**支持的导出格式**：ONNX、TensorRT、OpenVINO、TorchScript、CoreML、TF SavedModel、TF Edge TPU、PaddlePaddle、NCNN、MNN。

### 3.5 运行环境支持

| 平台 | 设备参数 |
|------|----------|
| NVIDIA GPU | `device=0` 或 `device=cuda:0` |
| AMD GPU | `device=0` (ROCm构建) |
| Intel GPU | `device=xpu:0` |
| Apple Silicon | `device=mps` |
| Huawei Ascend NPU | `device=npu:0` |
| CPU | `device=cpu` (默认) |

## 4. 不同版本 YOLO 怎么选？

### 4.1 系列选择：YOLO26 vs YOLO11

| 对比项 | YOLO26（最新） | YOLO11 |
|--------|---------------|--------|
| 发布 | 2026 | 2024.09 |
NMS | **端到端NMS-Free**（默认） | 需要NMS后处理 |
| 回归 | DFL-Free（更简洁） | 含DFL |
| 优化器 | MuSGD（SGD+Muon混合） | AdamW/SGD |
| 检测COCO mAP | **40.9-57.5** | 39.5-54.7 |
| CPU速度 | 比YOLO11快43%（n版） | 基准 |
| 生产推荐 | ✅ 推荐 | ✅ 推荐 |

**建议**：新项目直接用 **YOLO26**；已有YOLO11项目可平滑迁移。

### 4.2 模型尺寸选择

每个系列提供5个尺度，适用于不同场景：

| 尺度 | 参数量(M) | COCO mAP | T4延迟(ms) | 适用场景 |
|------|-----------|----------|------------|----------|
| **n** (nano) | 2.4 | 40.9 | 1.7 | 边缘设备、移动端、超高FPS |
| **s** (small) | 9.5 | 48.6 | 2.5 | 轻量部署、无人机 |
| **m** (medium) | 20.4 | 53.1 | 4.7 | 通用服务器、平衡场景 |
| **l** (large) | 24.8 | 55.0 | 6.2 | 高精度需求 |
| **x** (xlarge) | 55.7 | 57.5 | 11.8 | 离线处理、最高精度 |

### 4.3 任务匹配

| 需求 | 推荐模型后缀 |
|------|-------------|
| 目标检测 | `yolo26n.pt` |
| 实例分割（像素级掩码） | `yolo26n-seg.pt` |
| 语义分割（场景理解） | `yolo26n-sem.pt` |
| 深度估计 | `yolo26n-depth.pt` |
| 图像分类 | `yolo26n-cls.pt` |
| 人体/动物姿态 | `yolo26n-pose.pt` |
| 旋转目标检测 | `yolo26n-obb.pt` |
| 开放词汇检测 | `yoloe26x.pt` |

### 4.4 选型决策流程图

```
需要做什么任务？
├── 检测/分割/分类 → 选YOLO26系列
├── 已有YOLO11项目 → 可迁移到YOLO26
├── 边缘设备（<100MB） → 选 n 或 s 尺度
├── 服务器部署 → 选 m 或 l 尺度
├── 追求最高精度 → 选 x 尺度
└── 需要开放词汇 → 选YOLOE-26
```

## 5. 如何训练自己的数据集？

### 5.1 数据集格式

Ultralytics支持多种标注格式，推荐转换为YOLO格式（`.txt`）：

```
dataset/
├── images/
│   ├── train/        # 训练集图片
│   └── val/          # 验证集图片
└── labels/
    ├── train/        # 训练集标注
    └── val/          # 验证集标注
```

标注文件格式（每行一个目标）：
```
<class_id> <x_center> <y_center> <width> <height>
```
所有坐标均为**相对值**（0~1），归一化到图像尺寸。

### 5.2 数据集配置文件（data.yaml）

```yaml
# dataset.yaml
path: ./dataset          # 数据集根目录
train: images/train      # 训练集路径
val: images/val          # 验证集路径

# 类别定义
names:
  0: person
  1: bicycle
  2: car
  3: motorcycle
```

### 5.3 训练命令

**Python API：**
```python
from ultralytics import YOLO

# 加载预训练模型（推荐迁移学习）
model = YOLO("yolo26n.pt")

# 开始训练
results = model.train(
    data="dataset.yaml",    # 数据集配置
    epochs=100,             # 训练轮数
    imgsz=640,             # 输入图像尺寸
    batch=16,              # 批次大小
    device=0,              # GPU设备
    lr0=0.01,              # 初始学习率
    patience=50,           # 早停轮数
    save_period=10,        # 每N轮保存一次
)
```

**命令行：**
```bash
# 从预训练模型微调
yolo detect train data=dataset.yaml model=yolo26n.pt epochs=100 imgsz=640

# 从空白网络从头训练
yolo detect train data=dataset.yaml model=yolo26n.yaml epochs=100 imgsz=640

# 多GPU训练
yolo detect train data=dataset.yaml model=yolo26n.pt epochs=100 imgsz=640 device=0,1

# 空闲GPU自动选择
yolo detect train data=dataset.yaml model=yolo26n.pt epochs=100 imgsz=640 device=-1
```

### 5.4 训练恢复

```python
# 从上次中断处继续训练
model = YOLO("runs/detect/train/weights/last.pt")
results = model.train(resume=True)
```

### 5.5 关键超参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `epochs` | 100 | 训练轮数 |
| `imgsz` | 640 | 输入图像尺寸 |
| `batch` | 16 | 批次大小 |
| `lr0` | 0.01 | 初始学习率 |
| `lrf` | 0.01 | 最终学习率因子 |
| `momentum` | 0.937 | SGD优化器动量 |
| `weight_decay` | 0.0005 | 权重衰减 |
| `optimizer` | `auto` | 优化器（auto/MuSGD/AdamW/SGD） |
| `close_mosaic` | 10 | 最后N轮关闭数据增强 |
| `patience` | 100 | 早停 patience |

### 5.6 训练监控

训练过程中会自动生成：
- `runs/detect/train/` 目录，包含：
  - `results.png` — 训练曲线图（损失、mAP等）
  - `confusion_matrix.png` — 混淆矩阵
  - `weights/best.pt` — 最优模型权重
  - `weights/last.pt` — 最后保存的权重

## 7. 训练特定场景新模型：以"警服检测"为例（2026-10-06 追加）

> 背景：公司视频/安防平台需要检测特定对象（如穿警服的人员）。COCO 80 类里**没有警服/制服类**，现有 YOLO 预训练模型开箱检不出，必须自定义数据集微调。

### 7.1 路线选择（先定问题定义）

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 整体检测（推荐首选）** | 把"穿制服的人"作为一个整体类别 `police_person` 做目标检测 | 只关心"画面里有没有穿警服的人"，标注快、效果好 |
| B. 人+属性两段式 | 先 person 检测（COCO 现成）→ 裁剪人体区域 → 分类器（YOLO-cls/ResNet）判"是否警服" | 需要同时输出"普通行人"和"警服人员"两个类别、且警服款式多样的场景 |
| C. 开放词汇检测（YOLOE） | `yoloe26` + 文本 prompt "police uniform officer"，免训练 | **仅原型验证**：快速确认场景可行性 + 预标注（见 7.2），精度和速度不及微调模型，不做生产 |

注意：不要只框"衣服"（无头/被遮挡时框不稳），**框整个穿着该制服的人**，标注一致性最好。

### 7.2 数据采集与标注（占 70% 工作量）

**数据量参考**（单类别，经验值）：

| 数据量 | 效果 |
|---|---|
| 100~300 张 | 原型/内部演示 |
| 500~2000 张 | 生产可用（覆盖主要场景变化） |
| 5000+ 张 | 高召回、复杂场景（遮挡/远距离/多款式） |

采集要点（针对警服）：
- **覆盖变量**：季节（夏执勤服/春秋/冬装/作训服/反光背心）、光照（白天/夜间/逆光/红外补光）、距离（近景特写~200 米外小目标）、遮挡（人群/车辆/柜台）、角度（正/侧/背）；
- **负样本很重要**：必须混入大量"相似但非警服"的样本（保安制服、快递员、消防员、黑色西装、其他深色制服），否则误报爆炸——负样本不需要框，留空标注即可，比例建议 1:1~1:2；
- **来源**：平台存量监控录像抽帧（最有价值，分布与线上一致）、公开数据集（如 UCF-Crime、DUT 数据集含 police 类）、手机拍摄；
- **脱敏**：涉及人脸的标注数据注意内部合规，只标不存原视频。

**标注工具对比**：

| 工具 | 部署 | 特点 | 适合 |
|---|---|---|---|
| **CVAT** | Docker 自部署（团队已有 Docker 环境） | 专业级：矩形/多边形/关键点，团队协作，支持 SAM 自动标注，导出 YOLO 格式一键完成 | 本项目首选 |
| Roboflow | SaaS（数据出境需评估） | 最流畅的标注+增强流水线 | 数据无合规问题时 |
| Label Studio | Docker 自部署 | 多任务通用（检测/分类/文本），模板多 | 未来要混标分类/人脸 |
| X-AnyLabeling | 本地桌面（单 exe） | 内置 SAM/YOLO 辅助预标注 | 单人快速标注 |
| LabelImg | pip 安装 | 极简，只支持矩形框（Pascal VOC/YOLO 格式） | 小批量 |

**提效技巧——用现成模型预标注**：
1. YOLOE（`yoloe26x.pt`）用文本 prompt "police officer / uniformed police" 对全量抽帧跑一遍粗框；
2. COCO person 检测框住所有人 → 人工在框上确认/删改（比从零画框快 3~5 倍）；
3. SAM（Segment Anything）多边形辅助，需要实例分割任务时用。

**数据集结构**（YOLO 格式，同 5.1）：

```
police_dataset/
├── images/{train,val,test}
├── labels/{train,val,test}     # 0 x_center y_center w h（归一化）
└── data.yaml
```

```yaml

train: images/train
val: images/val
test: images/test
names:
  0: police_person      # 穿警服的人
  1: civilian           # （可选）普通行人，正负样本都想要时加
```

划分比例 7:2:1，同一摄像头/同一视频的帧**不能跨集**（时序泄漏会导致 mAP 虚高）。

### 7.3 训练方法与关键超参

**方法定案：COCO 预训练权重微调（transfer learning），不要从头训**（除非数据 >2 万张）。

```bash
# 单卡 2080 Ti 11GB 实测可行（n/s 尺度）
yolo detect train data=data.yaml model=yolo26s.pt \
  epochs=150 imgsz=640 batch=16 device=0 \
  patience=30 close_mosaic=10 plots=True
```

| 参数 | 建议 | 说明 |
|---|---|---|
| 基座 | yolo26s 或 m | 监控小目标多时用 s/m；边缘部署才用 n |
| imgsz | 640 起步 | 小目标（远距离警服）试 960/1280，精度↑显存↑ |
| epochs | 100~200 | 小数据集易过拟合，看 val 曲线配合 patience |
| batch | 16~32 | 显存不够就减半，或用 AMP（默认开） |
| 冻结 | `freeze=10` | 数据 <500 张时冻结前 10 层，防灾难性遗忘 |
| 增强 | 默认 mosaic 即可 | 夜间监控场景加 `copy_paste`、降低 `hsv_v` 亮度扰动 |
| 类别不平衡 | 自动调 `box`/`cls` gain | 警服样本远少于行人时，val 上分别看两类 P/R |

**训练硬件**（内网现状）：2080 Ti 单卡可跑 n/s/m（imgsz≤960）；l/x 或 imgsz 1280 用 L20 48GB。训练产物 `best.pt`。

### 7.4 评估与上线

1. **评估**：`yolo val` 出 P/R/mAP50-95；重点看**远距离小目标的 recall** 和**负样本误报率**（把 50 张纯负样本单独过一遍数误报个数，比看 mAP 更贴近业务）；
2. **可视化抽查**：`yolo predict` 跑 test 集存图人工过一遍（自动指标骗人，漏检模式要人眼确认）；
3. **导出部署**：`model.export(format="onnx")` / TensorRT（NVIDIA 线）；导出后**必须复测一遍精度**（FP16 一般无损，INT8 需校准集）；
4. **监控闭环**：线上误检/漏检的帧回流进数据集（active learning 迭代），每季度重训一次；
5. 与平台集成：走现有推理服务化模式（与 OCR/人脸服务同套接口），或直接 ONNX Runtime 嵌入检索流水线。

### 7.5 现有 YOLO 预训练模型能干什么（对照"警服"需求）

| 需求 | 现成模型 | 结论 |
|---|---|---|
| 检测警察/警服 | COCO 80 类无人物属性类 | ❌ 需自训 |
| 检测"人" | COCO person（yolo26 系列全部支持） | ✅ 直接用，做两段式方案的第一段 |
| 开放词汇试检"police uniform" | YOLOE-26（文本 prompt） | ⚠️ 可试，仅限原型/预标注 |
| 人脸（制服识别辅助） | 平台已有 InsightFace/人脸识别（见 OCR/人脸识别调研） | ✅ 可与 YOLO 结果联用 |
