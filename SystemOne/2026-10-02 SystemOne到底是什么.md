# System One 到底是什么？

> 一文讲透 2026 年 9 月新出现的一类模型：从命名由来、核心契约，到工程落地姿势。
>
> 整理日期：2026-10-02

---

## 一句话定义

**System One 模型 = 专做"快速直觉判断"的模型**。给它一段文本（或 JSON 状态）和一个**答案范围已知**的问题，它返回**带类型的答案 + 概率**（是/否、N 选 1、打分）——而且**绝不**生成散文、代码或解释。

它不是"更小的 LLM"，而是一个**概率决策引擎**，占据了"确定性业务代码"与"完整生成式推理（LLM）"之间一个全新的架构位置。

## 命名由来：致敬卡尼曼《思考，快与慢》

| | System 1（快思考） | System 2（慢思考） |
|---|---|---|
| 人类特征 | 快速、直觉、自动——还没想清楚缘由就先做出的判断 | 缓慢、审慎、费力——刻意推演的过程 |
| AI 对应 | **System One 模型**（2026 年新品类） | LLM 在做规划、写作、解释时的那套推理 |

设计动机很直接：生产环境里大量 AI 开销，花在了"整个输出最终被压缩成一个布尔值 / 一个枚举 / 一个 1–5 分评分"的 LLM 调用上——为开放式生成付费、等数秒 token、解析 JSON、然后把大部分内容丢掉，还顺带承接了 LLM 的延迟、成本和"自信地编造答案"的毛病。System One 模型就是冲着这种**错配**来的。

## 核心契约：你定义决策空间，它只在空间内给意见

- **输入**：状态（文本，或由文本字段组成的 JSON 对象）+ 一个或多个问题；每个问题附带**预先定义好的合法答案集合**。
- **输出**：带类型的答案及其概率。多个问题共享同一状态时**独立、并行评估**，一次调用即可从一份文档中做出多个决策。
- **不生成**：散文、代码、解释、任意 JSON。

关于"不会幻觉"，需要精确理解：由于答案空间固定，它**无法返回你定义之外的选项**（格式幻觉被消除，`Choice["approve","deny"]` 永远不会返回"或许核销掉"）。但它**仍可能自信地给出语义错误的正确答案格式**——而这种"格式完美但判断错误"的结果，可能比 LLM 的格式错误**更危险**，因为它能干净利落地通过校验。

## 代表：Jev（TypeSafe AI，2026-09-15 发布）

Jev 是第一个 System One 模型，暴露三个"决策原语"，几乎每个用例都是它们的组合：

| 原语 | 问题形态 | 返回 | 典型角色 |
|---|---|---|---|
| **Noul** | 一个是/否判断（"这张工单是在申请退款吗？"） | [0,1] 的概率 | 标记、门控、独立判据 |
| **Choice** | 在 N 个已定义选项中选一个（"这归哪个团队负责？"） | 所选选项、各选项概率、置信度 | 路由、分类、工具/模型选择 |
| **Score** | 依据评分标准的有序评级（"这起事故有多严重？"） | 期望分数、各等级概率、置信度 | 优先级排序、风险、质量评估 |

心智模型：**你定义决策及其答案空间；Jev 在其中返回一个"经过校准的意见"。** 这与"prompt 一个 LLM 然后祈祷 JSON 能解析成功"是根本不同的契约。

## 定位：System One vs System Two（LLM）

| 维度 | System One（Jev） | System Two（LLM） |
|---|---|---|
| 输出 | 带类型的答案 + 概率 | 自由形式的文本/代码 |
| 擅长 | 有界的语义判断 | 开放式推理、综合、生成 |
| 延迟 | 亚秒级（厂商称约 70–500 毫秒） | 数秒 |
| 成本特征 | 每次决策极低 | 更高，随生成 token 数增长 |
| 格式错误 | **不可能**（答案空间固定） | 可能（格式错误、捏造字段） |
| 解释 | 无 | 有 |
| 由谁消费 | 软件 | 人与软件 |

一个反直觉的点：**它最强的对手未必是另一个 LLM**。对于稳定、标注良好的分类问题，传统训练的分类器可能更便宜且可完全自托管。System One 模型的优势体现在：**类别在运行时定义**（为每个新问题定制分类器不划算）、以及你希望把**经过校准的概率**作为一等公民输出（而不是从生成文本里硬套出来的数字）。

## 什么时候该用它：五条判断标准

一个问题同时满足以下属性，才是好候选：

1. 输入携带着**简单规则无法解决的语义歧义**；
2. 可能答案的集合**在推理之前就已知**；
3. 应用需要的是**机器可消费**的结果，而非散文；
4. 判断可以从现有状态中做出，**无需一长串推理**；
5. 它**发生得足够频繁**，以至于 LLM 的延迟与成本举足轻重。

## 典型用例

1. **意图路由与分类**：一条支持消息进来，一个 `Choice` 选出归属队列、一个 `Noul` 标记是否请求退款、一个 `Score` 评定紧急度——同一状态、一次调用，队列名保证是真实存在的那个。
2. **相关性评分与检索门控**：开源工具 `jevgrep` 用它判断代码库中文件夹/文件/声明的相关性，让编码智能体"描述行为"即可定位代码，作者报告基准子集上智能体成本削减约 40%。同样模式适用于 RAG：先广检索，再让它在内容抵达生成器之前评估相关性与证据支持度。
3. **实时决策回路**：LLM 太慢的地方，System One 可以跑在回路内。`jev-trader` 是个极端案例——做市机器人必须在单个约 300 毫秒的区块内读订单簿、定方向、下单。游戏、机器人、控制系统、实时个性化都是这类回路。
4. **智能体与工具门控**：开放式任务里充满了有界选择——用哪个工具？继续还是停？这个动作有风险吗？Vercel 和 LangChain 已将其用于工具路由与动作前风险检查。
5. **生产环境评估**：不必对轨迹抽样做昂贵的 LLM-as-a-judge，可在每条轨迹上跑廉价的带类型评估器（正确性、安全性、用户挫败感、策略合规性）。Langfuse 于 2026 年 9 月以实验性 Jev 评估器的形式上线了该能力。

## 架构模式：感知概率的选择性自动化

最重要的理念（也是团队最容易搞错的）：**一个 Jev 答案不是一条采取行动的指令，它是一个概率。** 拿这个概率做什么，是独立的、确定性的、由你自己掌控的策略决策——且应当取决于**判断错误的后果**，而不只是置信度数字。

"置信度 ≥ 0.8 就行动"的一刀切规则是糟糕的设计。自动打营销标签能容忍的不确定性，远高于放款、拒赔或改动生产基础设施。正确形态是置信度门控级联：

```text
input → 确定性校验 → 检索并最小化上下文
      → Jev 决策层 → 带类型答案 + 概率
      → 风险感知策略引擎:
            高置信 + 低后果      → 自动执行
            中间带 / 需推理      → 升级给 LLM
            不确定 / 高后果      → 人工复核
            违反策略             → 阻断 / 安全兜底
      → 捕获结果 → 校准监控 → 反馈回策略
```

经济账：设 `C_J`、`C_F`、`C_H` 分别为一次 Jev 调用、一次回退 LLM 调用、一次人工复核的成本，`r_F`、`r_H` 为各自上报比率，则每次决策的期望成本约为 `C_J + r_F·C_F + r_H·C_H`。Jev 的价值正是**在压低上报比率的同时不抬高下游错误率**。本质上是经典的**选择性分类**权衡（以较低覆盖率换较低错误率）+ **校准**（判"90%"的事，实际发生也约 90%）。

## 局限性：当架构约束看，别当脚注

| 局限 | 设计应对 |
|---|---|
| 不擅长精确算术与计数 | 所有数学运算在普通代码中完成 |
| 不擅长日期/时间比较 | 确定性地解析和比较日期 |
| 多跳推理表现下降 | 拆解题，或路由给 LLM |
| 无关长输入导致"上下文腐烂" | 调用前检索并裁剪状态 |
| 对判据的字面化理解 | 明确定义正向和负向边界 |
| 易受状态中的提示注入攻击 | 把输入当不可信；硬性管控留在代码里 |
| 仅支持文本，英语最强 | 图像/音频先预处理；其他语言用自己的数据验证 |
| 无生成、无解释 | 需要散文就与 LLM 搭配 |

## 成熟度风险

- 发布仅数周（截至 2026 年 10 月初），**无同行评审论文、无公开权重/参数量、无可复现训练规格**；
- "面向校准决策的强化学习"是**厂商描述的范式，而非经过验证的范式**；
- 吸睛数字（厂商称成本最多降约 400 倍、延迟最多降约 200 倍）均为**第一方基准**——有待在自己的工作负载上复现的假设，不是 SLA；
- 目前**仅托管服务，无自托管选项**，数据驻留敏感的场景要提前评估。

## 工程 / 运维建议

1. **置于提供方无关的决策服务之后**：别让每个应用直连厂商 API。对外暴露内部"决策"契约（状态、问题、允许的答案、风险类别），返回规范化结果——隔离凭据、集中治理阈值、可对替代方案影子测试、留好退出之路。
2. **锁定模型版本**：`latest` 别名会随新版本漂移，而你针对某版本校准的置信度阈值会被一次无通知升级悄悄作废。升级按**模型迁移**走：回放、影子、金丝雀，再全量。
3. **打磨判据，而非提示**：回报来自把模糊判断拆成原子问题（"保单条款是否支持？""证据多充分？"），再用确定性策略代码组合；算术、日期、不变量、副作用全部留在软件里。
4. **治理附着于系统，而非模型**：嵌入招聘、放贷、安全工作流的非生成式决策组件，同样逃不开 EU AI Act、NIST AI RMF 等义务。记录模型版本、决策定义、策略版本与结果，为高影响决策保留人工申诉通道。
5. **引入节奏**：影子 → 校准 → 置信度门控 → 金丝雀 → 扩展；配合确定性安全边界和始终可用的上报通道。

**结论**：System One 模型（Jev）是一个令人兴奋的**专用加速器**，不是可以押上整个平台的根基。

## 容易混淆的点

- 与 **Meta 的 JEPA 系列模型毫无关系**，纯属撞名；
- 它**不是 mini LLM**：不能聊天、不能生成，输出永远是"答案 + 概率"。
