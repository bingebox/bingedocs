## 总体结论

两份文档**高度互补且结论一致**，可以合并成一份可执行计划：

1. **市场侧（手册一）回答了"往哪走"**：2026 年 AI 岗位的核心关键词是 Agent（58% 提及）→ RAG（53%）→ 微调（26%）→ 多模态（13%），且 96% 岗位要求 5 年+ 生产系统经验——**纯调 API 的岗位已基本消失，"工程化 + 评测 + 行业 know-how"是分水岭**。
2. **路线侧（手册二）回答了"怎么走"**：12 个月五阶段、每阶段一个可部署通关项目、eval 是贯穿主线。
3. **两份文档的关键分歧点**（评估中需要取舍的地方）：
   - 手册一将 **LangChain（34%）** 列为高需求核心项，手册二认为 LangGraph 才是 Agent 编排的强优先项，且"框架会过时，不迷信框架"。**采纳手册二**：LangChain 会即止，主攻 LangGraph + 裸 SDK。
   - 手册一给出"Python→PyTorch→NLP→Docker"的筑基顺序（面向零基础），手册二的地基自检是"FastAPI+React+Postgres+Docker 的 CRUD 服务"（面向有经验的开发者）。**采纳手册二**，且个人已有生产环境经验，阶段 0 可直接压缩。
   - 手册一强调 PyTorch（36% 提及），手册二对模型层的要求是"理解+会用，不要求造轮子"。对个人情况**折中**：PyTorch 会跑推理/加载权重/写简单训练脚本即可，不投入预训练级时间。
4. **个人定位**：不是转行者，是已有后端/运维平台经验（Docker Swarm/K8s、ELK→Loki、Milvus）、有本地 LLM 推理实操（2080 Ti ×2 llama.cpp 52 t/s、L20 FP8+vLLM 规划）、有 CV 领域积累（OCR/人脸/YOLO）的工程师。因此 12 个月路线**整体压缩约 30%，重心从"学"移到"交付可评估的作品集"**，多模态（手册一列为前沿王牌方向）恰好是个人差异化优势位，应提前投入而非放到最后。

**一句话计划：9 个月内完成 P1–P5 五个可部署项目（RAG 问答 + 研究型 Agent + 自部署 vLLM 后端 + AI SaaS），以"截图多模态智能检索系统"这类领域项目作为差异化王牌，每 8 周一个里程碑 + 评测报告。**

### 1.3 市场判断（对手册一结论的个人解读）

- **城市/薪资**：深圳 51% 占比 + 金融/医疗/制造行业分布。个人在汕头，目标市场实际是**远程/深圳岗位**或"通用平台能力 + 本地行业 know-how"路线；薪资中位数 5.8-8.6 万/月对 5 年+ 经验者才有意义，**短期（1 年内）目标应是作品集 + 可讲的生产案例，而非直接对标中位数**。
- **学历门槛**（85% 硕士）是算法/研究岗的门槛，对**应用/全栈工程岗**（20% 占比 + 5% 全栈架构师）不是硬约束——本计划瞄准的正是后者，绕开学历墙。
- **行业选择**：手册一列的金融/医疗与个人背景不匹配；个人最强行业 know-how 是**安防/IoT/视频结构化**（公司平台即此方向），多模态检索方向应绑定这个领域做作品集，对应手册一"行业化 = 竞争力"的判断。

## 二、个人定制路线图（9 个月，四阶段）

> 相比手册二 12 个月五阶段的调整：阶段 0 压缩（工程地基已有）、阶段 4 前置内容（vLLM 实操已领先）、P6 多模态提前（差异化王牌）、总时长 9 个月。节奏：主线每周 ≥ 12h，TS+Vue 方案并行每周 4h（见关联文档）。
>
> 硬件优势：双 2080 Ti（llama.cpp 已跑通）+ L20 48GB（FP8+vLLM 主力）——**P4 压测与微调全部用本地硬件完成，零云成本**。

### 阶段 A：LLM API 工程化（第 1–6 周）→ 通关 P1

**前置**：`LLM/2026-08-31 LLM使用教程` 已覆盖 Transformer 直觉/Token 成本/结构化输出，本阶段只做缺口。

- [ ] 生产级 LLM 客户端封装（Python）：超时、指数退避、多模型 fallback（L20 vLLM 主 + 云 API 备）、Token 用量日志、语义缓存——直接对接现有本地 vLLM 端点（`~/.hermes/config.yaml` 的 custom provider 模式即是雏形）。
- [ ] Prompt 场景库：10 种场景 × 3 个边界用例（翻译/抽取/分类/改写/评分/代码生成/JSON 结构化/摘要/Agent 工具选择/安全拒绝）。
- [ ] Chat 前端（用 TS+Vue 并行线的技术栈，流式 SSE 打字机、停止生成、历史会话、用量统计页）。
- [ ] **P1 交付**：流式 Chat 应用，Docker 一键部署 + README + 用量数据。

**自测关**（答不上=未过关）：Token 成本构成与缓存收益；流式接口"可取消+断线不丢"的实现；模型升级后的 eval 回归流程。

### 阶段 B：RAG 全链路 + 评测体系（第 7–14 周）→ 通关 P2

**个人优势**：检索基础设施选型（OpenSearch/Easysearch、Milvus）调研已完成，本阶段重点在**调优方法论与 eval**，而非选型。

- [ ] 教材主线：Datawhale《All-in-RAG》+ RAGas 文档 + LlamaIndex 文档。
- [ ] chunking 对比实验：同一批 PDF（用公司平台截图/文档类真实数据）跑 3 种切分策略，量化召回。
- [ ] 混合检索：BM25 + 向量 + rerank 全链路，与单路对比（注意：不同语义空间向量拆索引/带 type tag——个人调研已有此结论，直接应用）。
- [ ] **强制动作**：从本周起建 50 题评测集，任何 prompt/chunking/模型改动必须跑 Recall/Faithfulness/答案相关性并记录前后分数（`badcase.md` 同步维护）。
- [ ] **P2 交付**：知识库问答系统——PDF/网页摄取、答案带出处引用、检索分数透明化、附评测报告。

**自测关**：固定长度 chunking 为何失败；BM25 与向量各解决什么、rerank 放哪；如何避免数字类问答编造。

### 阶段 C：Agent 与多步系统（第 15–22 周）→ 通关 P3

- [ ] LangGraph 状态机 + 工具设计（5 个工具：搜索/查库/写文件/调 API/计算，每个写错误信息回传规范）。
- [ ] 失败可恢复 Agent：任意步骤失败→重试/降级/人工介入。
- [ ] MCP：已有日常使用经验，本阶段做一个**自建 MCP server**（把公司平台某能力封装成工具），从消费者变提供者。
- [ ] **P3 交付**：研究型 Agent——自然语言任务→自主规划→检索→产出带引用报告，全程 trace（Langfuse 或 Phoenix 自建）。

**自测关**：Agent 循环调用的多层防御；说出 3 个"不该用 Agent、一个函数就够"的任务反例。

### 阶段 D：模型层收尾 + 多模态王牌 + 生产化（第 23–36 周）→ 通关 P4/P6/P5

**顺序说明**：手册二把 vLLM 放第 4 阶段、多模态做 P6 加分项；个人 vLLM 已领先、多模态是差异化优势，故合并并提前。

- [ ] **P4（第 23–28 周）**：把 P2 的 RAG 系统切到 L20 自部署 vLLM 后端（FP8），压测吞吐/TTFT/P99 并调并发/显存配置；用 ≤2k 条数据做 LoRA 实验（场景：平台领域术语改写或截图分类），诚实记录提升与没提升的场景；产出《闭源 API vs 自部署》成本/效果/延迟对比报告（数据源：现有 2080 Ti llama.cpp 与 L20 vLLM 实测，零云成本）。
- [ ] **P6 提前（第 25–32 周，与 P4 并行）**：**截图多模态智能检索系统**——OCR+人脸+YOLO+VLM（SigLIP2 类多模态嵌入）+ 向量检索，把 `mydocs` 里已有调研（PaddleOCR/InsightFace/YOLO/多模态检索）变成可部署产品。这是作品集里最差异化的一件：市面 AI 全栈求职者少有"视频结构化领域 RAG/Agent"实战。
- [ ] **P5（第 29–36 周）**：AI SaaS 化——多用户/配额计费/管理后台/eval 看板/部署流水线，把 P2 或 P6 系统改造升级（不重复造轮子），开源 + 高质量 README + 架构图 + eval 曲线。
- [ ] 安全与可观测：prompt 注入红队自测、输出护栏、敏感数据脱敏；全链路 trace + 成本看板（复用 Loki 运维经验做可观测方案）。

**自测关**：月 10 万次调用的成本预算（P99 3s）；线上 badcase 5 分钟定位到 prompt/检索/模型层。

## 三、每日纪律与红线（沿用手册二，个人化修订）

### 每周节奏（主线 12h + 并行 4h）

- 2h 输入：读源码/文档（LangGraph、vLLM、RAGas 为必读源码；每月 2–3 篇 paper 摘要，手册一要求）。
- 6h 实操：推进当前阶段项目。
- 2h 评测：跑 eval、看 trace、记 badcase。
- 2h 输出：更新博客/笔记。
- 并行 4h：TS+Vue / Rust。

### 红线规则

- 不写没有评测的 prompt/chunking 改动。
- 不把生产密钥、未脱敏数据贴进 prompt、博客或评测集（安防截图数据尤其注意人脸信息脱敏）。
- 不在没有超时/重试/降级的设计里上线 LLM 调用。
- 框架用熟后，裸 SDK 重写一遍核心链路（防"框架即能力"陷阱）。
- **新增（个人）**：本地硬件跑不动的实验（如 70B+ 模型压测）不硬撑，写"结论外推 + 依据"即可，不伪造数据。

### 常见误区对照（手册二原表，保留）

| 误区 | 心法 |
|------|------|
| 先刷完课再动手 | 每个知识点 24 小时内落到代码 |
| 微调万能 | 顺序：Prompt → 结构化输出 → RAG → 微调，微调先用 2k 条验证收益 |
| 框架即能力 | 对 Token/延迟/成本/非确定性的理解不会过时 |
| demo 炫技 | 生产价值 = 稳定性 × 成本 × 可评估性 |
| 什么都上 AI | 能用 10 行规则解决的别花 10 美分调 LLM |
| 孤狼式学习 | 第 8 周起强制输出，让市场校准方向 |

## 五、需要拍板的决策点

1. **P5 底座选 P2 还是 P6 改造**：P2（知识库问答）更稳妥、完成度高；P6（多模态检索）差异化强但复杂度高。建议 P6，风险是周期溢出 2–3 周。
2. **博客载体**：mydocs 内网 wiki（安全但无曝光）vs 公开平台（求职杠杆但需脱敏审查）。建议：技术通用部分（vLLM 压测/LoRA 实验/eval 方法论）公开写，公司平台相关内容只留内网。
3. **P3 的自建 MCP server 封装哪个平台能力**：建议选只读、低风险的接口（如告警查询类），避开写操作。
4. **时间预算确认**：主线 12h/周 × 36 周 ≈ 430h。如果实际只能稳定 8h/周，P6 应降级为"P2 加多模态模块"而非独立系统，总周期回到 12 个月（手册二原节奏）。
