# Open-Design系统简介与使用


## 1. 前言

### 1.1 来由

在 UI/UX 设计领域，Figma、MasterGo 等在线设计工具已经成为行业标配。然而这些工具要么是 SaaS 服务（依赖云端、付费、受限于平台），要么是桌面应用（安装体积大、更新慢、扩展性差）。对于开发者来说，如果能有一个**可本地部署、可二次开发、开源可定制**的在线设计工具，就能在原型设计、界面规划、团队协作等场景中自由掌控。

Open-Design 正是在这样的背景下诞生的开源在线图形设计工具。它由开发者 zyronon 创建，目标是打造一个类 Figma/MasterGo 的在线设计平台——**基于浏览器运行、功能完整、代码开源、可自由修改和扩展**。项目地址：

- **GitHub**：https://github.com/zyronon/open-design
- **在线预览**：https://open-design-git-vite-dev-zyronons-projects.vercel.app/
- **联系邮箱**：zyronon@163.com
- **开源协议**：MIT License

截至调研时，项目已有 16+ GitHub Stars，核心功能已覆盖图形绘制、元素操作、属性编辑等设计工具的基本需求，适合个人开发者在原型设计、界面草图、简单设计稿等场景使用。

### 1.2 定位与作用

| 维度 | Open-Design | Figma | MasterGo | Excalidraw |
|------|-------------|-------|----------|------------|
| 部署方式 | 本地自建 | 云端 SaaS | 云端 SaaS | 云端 + 自托管 |
| 开源 | ✅ 完全开源 | ❌ 闭源 | ❌ 闭源 | ✅ 开源 |
| 定制性 | 可二次开发 | 插件受限 | 插件受限 | 可二次开发 |
| 费用 | 免费 | 免费/付费 | 免费/付费 | 免费 |
| 功能定位 | 图形绘制 + 界面设计 | 完整 UI/UX 设计 | 完整 UI/UX 设计 | 手绘风格白板 |

**核心价值**：

1. **零成本使用**：MIT 协议开源，无需付费，本地部署无使用限制
2. **开发者友好**：基于 React + TypeScript，源码可读可改，可集成到自有项目
3. **技术学习价值**：Canvas 渲染、状态管理（Redux）、矩阵运算（gl-matrix）等核心技术的实战示例
4. **设计能力补充**：在 Mermaid 和 PlantUML 等文本设计工具之外，提供可视化拖拽设计能力

### 1.3 功能概览

Open-Design 的核心功能围绕「图形设计与编辑」展开：

- **Canvas 画布**：基于 HTML5 Canvas 的无限画布，支持缩放、平移操作
- **图形绘制**：矩形、圆形、线条等基本几何图形
- **元素选择与变换**：选中、移动、缩放、旋转
- **属性编辑**：颜色、大小、位置等属性的可视化编辑
- **图层管理**：元素的层级关系管理
- **撤销/重做**：操作历史记录支持
- **导出功能**：设计结果导出为图片等格式

## 2. 安装

### 2.1 环境要求

在开始安装之前，请确保开发环境满足以下要求：

| 依赖项 | 最低版本 | 说明 |
|--------|----------|------|
| Node.js | ≥ 16.x | 运行时环境 |
| npm / pnpm | ≥ 7.x | 包管理器（任选其一） |
| Git | 任意 | 版本控制，用于克隆仓库 |
| 浏览器 | Chrome / Edge / Firefox 最新版 | 建议使用 Chrome 以获得最佳 Canvas 性能 |

### 2.2 安装步骤

#### 方式一：从 GitHub 克隆（推荐）

```bash
# 1. 克隆项目到本地
git clone https://github.com/zyronon/open-design.git

# 2. 进入项目目录
cd open-design

# 3. 安装依赖（npm）
npm install

# 或（pnpm）
pnpm install

# 4. 启动开发服务器
npm run start

# 5. 在浏览器中访问
# 打开 Chrome，访问 http://localhost:8000
```

启动后项目会自动在 `http://localhost:8000` 运行。

#### 方式二：使用 pnpm（包管理更快）

```bash
# 全局安装 pnpm
npm install -g pnpm

# 克隆并安装
git clone https://github.com/zyronon/open-design.git
cd open-design
pnpm install
pnpm start
```

pnpm 使用符号链接和硬链接，安装速度比 npm 更快，磁盘占用也更小。

### 2.3 构建生产版本

```bash
# 构建生产环境包
npm run build

# 构建产物输出到 build/ 目录
# 可使用任意静态服务器部署（nginx、Apache、GitHub Pages 等）
```

│  │  UI 组件   │ │  Canvas  │ │  颜色选择器等  │ │
│  │ (antd)    │ │  渲染层   │ │ (react-color)  │ │
│  └───────────┘ └──────────┘ └────────────────┘ │
├─────────────────────────────────────────────────┤
│                 State Layer                     │
│  ┌───────────┐ ┌──────────┐ ┌────────────────┐ │
│  │ Redux     │ │ Redux    │ │  状态 Actions   │ │
│  │ Toolkit   │ │ Store    │ │  和 Reducers    │ │

│  ┌───────────┐ ┌──────────┐ ┌────────────────┐ │

### 3.3 核心概念

在使用 Open-Design 之前，需要理解以下核心概念：

**1. 画布（Canvas）**
画布是设计工作的主区域，基于 HTML5 Canvas API 渲染。所有图形元素最终都绘制在 Canvas 上。

**2. 元素（Element）**
设计稿由多个元素组成，每个元素可以是：
- 矩形、圆形等基本图形
- 文本元素
- 组合元素（多个元素的集合）

**3. 状态管理（Redux）**
所有元素的位置、大小、颜色等属性都存储在 Redux Store 中。当状态改变时，Canvas 自动重新渲染。

**4. 矩阵变换（gl-matrix）**
图形的缩放、旋转、平移等操作通过矩阵运算实现。gl-matrix 提供了高效的 2D/3D 矩阵计算能力。

### 3.4 典型使用流程

```
1. 打开设计工具 → 进入空白画布
       ↓
2. 选择工具 → 从工具栏选择（选择/矩形/圆形/线条/文本等）
       ↓
3. 绘制元素 → 在画布上拖拽绘制图形
       ↓
4. 编辑属性 → 选中元素后在属性面板调整颜色、大小、位置
       ↓
5. 图层调整 → 在图层面板调整元素层级顺序
       ↓
6. 撤销/重做 → 通过历史记录恢复或重做操作
       ↓
7. 导出结果 → 将设计导出为图片格式
```

### 3.5 自定义与二次开发

由于项目开源且基于 React，开发者可以对其进行二次开发：

**1. 添加新图形类型**
在 `src/utils/` 中添加新的图形绘制逻辑，在 Canvas 渲染层注册新图形类型。

**2. 扩展属性面板**
在 `src/components/` 中新增属性编辑组件，通过 Redux Store 与元素属性绑定。

**3. 集成 AI 功能**
基于 Redux 的状态管理能力，可以轻松接入 AI 生成图形、智能配色等 AI 辅助设计功能。

**4. 团队协作功能**
Canvas 渲染层可接入 WebSocket 实现多人实时协作（类似 Figma 的实时编辑能力）。

## 4. 结束语

### 4.1 总结

Open-Design 是一个功能完整、架构清晰的开源在线图形设计工具。它证明了在浏览器中使用 React + Canvas 完全可以实现接近 Figma 的设计体验。

**项目亮点**：

1. **技术栈现代**：React 18 + TypeScript + Redux Toolkit，符合当前前端最佳实践
2. **架构清晰**：组件化 + 状态分离 + 工具函数解耦，代码可读性强
3. **功能实用**：涵盖了在线设计工具的核心功能（绘制、编辑、属性调整、图层管理）
4. **高度可定制**：MIT 开源协议 + 完整源码，可自由修改和扩展

### 4.2 适用场景

| 场景 | 推荐程度 | 说明 |
|------|----------|------|
| 原型设计 | ★★★★★ | 快速搭建界面原型，无需打开重型设计工具 |
| 团队协作 | ★★★★☆ | 可部署到内网，配合多人协作需求 |
| 技术学习 | ★★★★★ | 学习 Canvas 渲染、状态管理、矩阵运算的绝佳案例 |
| 界面定制开发 | ★★★★☆ | 嵌入自有业务系统，实现定制化的设计能力 |
| 生产级设计 | ★★★☆☆ | 功能尚不如 Figma 完善，适合轻量设计需求 |

### 4.3 与同目录其他设计工具的对比

本文档所在的 AIDesign 目录下还有其他设计工具文档，以下是 Open-Design 与它们的对比：

| 维度 | Open-Design | Mermaid | PlantUML | Excalidraw | OpenSpec |
|------|-------------|---------|----------|------------|----------|
| 类型 | 可视化设计工具 | 文本 UML | 文本 UML | 手绘白板 | 规范驱动开发 |
| 输入方式 | 鼠标拖拽 | 文本代码 | 文本代码 | 鼠标手绘 | Markdown 文档 |
| 输出 | 图形界面 | 渲染图表 | 渲染图表 | 手绘图 | 规范文档 |
| 适合场景 | 界面/原型设计 | 技术架构图 | 系统架构 | 头脑风暴 | 需求对齐 |
| 技术实现 | Canvas + React | Markdown 解析 | 文本解析 | Canvas + React | 规范管理 |

**推荐组合**：

- **需求阶段**：用 OpenSpec 对齐需求
- **架构阶段**：用 PlantUML 画系统架构，用 Mermaid 画流程图
- **原型阶段**：用 Open-Design 快速搭建界面原型
- **讨论阶段**：用 Excalidraw 进行手绘风格的头脑风暴

### 4.4 未来展望

随着 AI 辅助设计的发展，Open-Design 这样的开源设计工具将迎来新的机遇：

1. **AI 生成设计**：接入 LLM，通过自然语言描述自动生成界面原型
