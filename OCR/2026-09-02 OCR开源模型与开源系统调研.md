## 一、结论速览（TL;DR）

2026 年 OCR 技术格局的核心变化：**VLM（视觉语言模型）已取代传统流水线**（二值化→版面检测→文字切分→字符分类→语言模型纠错）成为文档理解主力。传统流水线每步误差会逐级放大，VLM 把整页图像一次前向，直接生成 markdown/JSON，布局、表格结构、文字内容一次出。

**两大阵营定位**：

| 阵营 | 代表 | 输出 | 适用 |
|---|---|---|---|
| **OCR VLM 模型** | PaddleOCR-VL-1.6（96.33% OmniDocBench v1.6）、DeepSeek-OCR、GOT-OCR 2.0、dots.ocr、Unlimited-OCR | 纯文本 / markdown / 结构化 JSON | 扫描件、截图、拍照件、混合排版；直接当"读图取字"引擎 |
| **文档解析系统** | MinerU（76.9k stars）、Marker 2、Docling、Surya、PDF-Extract-Kit | markdown / 结构化 JSON（带版面树、阅读顺序、表格网格） | PDF/办公文档批量入库、RAG 预处理 |

**核心选型结论**：
1. **精度优先（截图/扫描件/多语言）** → PaddleOCR-VL-1.6（0.9B，2GB 显存，100+ 语言，开源文档理解 SOTA）
2. **批量吞吐优先（同模板发票/表单/合同）** → DeepSeek-OCR（MoE，MIT）或 SGLang + 前缀缓存
3. **PDF 入库 RAG** → Marker 2 balanced（76.0% olmOCR-bench，B200 上 2.9 pg/s，是 MinerU pipeline 的 5.4 倍速度）或 MinerU（扫描/复杂版面最强，76.9k stars）
4. **商用许可无顾虑** → Docling（MIT）或 DeepSeek-OCR（MIT）；注意 **MinerU 超 100M MAU/月收 $20M 需商业授权，Marker 权重超 $5M 营收/融资需授权**
5. **老扫描件**是所有开源管线的共同短板（olmOCR-bench Old scans 各类管线最高仅 43.2），需路由到全页 VLM（Chandra 2 / dots.ocr 1.5 85+）

**对本公司的落地建议**（详见第七节）：截图检索系统的 OCR 层用 **PaddleOCR-VL-1.5/1.6 + vLLM**（单卡 L20 轻松，2080 Ti 上 FP16 2GB 也放得下），扫描件兜底保留 PP-OCRv5 经典流水线。

## 二、OCR 技术路线：2026 年发生了什么

### 2.1 传统流水线的困境

经典 OCR 是 5 级流水线：二值化 → 版面检测（layout detection）→ 文字区域切分 → 字符分类 → 语言模型纠错。干净印刷件上表现尚可，但：
- 每级误差累积（copy-on-write 式衰减）；
- 复印表格、混排脚本、手写批注、扫描件上精度快速塌方；
- 表格被压平成空白分隔的字符串，破坏 RAG 检索的键值关联。

### 2.2 VLM-OCR 的范式

VLM-OCR 把整页图像切成 patch 网格 → 视觉编码器 → 自回归语言解码器直接生成文本/结构化 JSON。**布局结构、表格单元格关系、文字内容在一次调用里全部处理**，prompt 控制输出格式（markdown 表格、JSON 键值对、纯文本），无需后处理逻辑。

API 面统一为 OpenAI Vision 规范（`/v1/chat/completions`），可直接替换 GPT-4o Vision / Claude 的文档读取调用。

**成本拐点**：2025-2026 年 1-3B 参数的 VLM 在印刷件上达到生产级精度，不再需要 H100 级硬件。10 万页/月的 Textract 账单 $1,500-10,000，自建 L40S/A100 上降到 $50-100/月，且文档不出 GPU 边界。

### 2.3 评测基准

- **OmniDocBench v1.5/v1.6**：文档理解综合基准（版面/表格/公式/多栏/手写），PaddleOCR-VL-1.5 以 94.5%（v1.5）夺冠，1.6 版本 96.33%。
- **olmOCR-bench**（Ai2）：1,403 个 PDF、约 8,400 个 pass/fail 单测，覆盖公式渲染、表格结构、阅读顺序、页眉页脚、老扫描件，Marker 2 用它做横评。
- **1-edit-distance**：PP-OCRv5 的排名指标，PP-OCRv5 在此榜上压过 GOT-OCR-0.5B、RolmOCR-7B、Qwen2.5-VL-72B、InternVL3-78B、Gemini 2.5 Pro。
- **注意**：不同基准的分数不可直接横比（评测脚手架、文档集、harness 均不同）。

**选型速记**：

- 学术论文公式 → **GOT-OCR 2.0**

### 3.3 部署

所有 VLM-OCR 都走 OpenAI Vision 接口，vLLM/SGLang 直接 serve。示例（PaddleOCR-VL-1.6 + vLLM）：

```bash
docker run --runtime nvidia --gpus all \
  -p 8000:8000 vllm/vllm-openai:latest \
  --model PaddlePaddle/PaddleOCR-VL-1.6 \
  --max-model-len 8192 \
  --limit-mm-per-prompt image=1 \
  --served-model-name paddleocr-vl
```

- **vLLM**：通用 OCR 工作负载。
- **SGLang**：大批量同模板文档场景，RadixAttention 前缀缓存复用共享 system prompt token，同模板工作负载吞吐 +20-40%。
- **DPI**：150-200 DPI 即可，更高 DPI 增加 token 数但精度增益不线性。
- **结构化 JSON**：用 system prompt 约束 schema（`text_blocks`/`tables`/`page_language`），印刷件上模型会可靠遵循。

### 4.2 三大系统架构拆解

**MinerU（重型选手）**
- 跑 OCR 时按需触发，输出 markdown 或带版面保留的 JSON；
- 扫描 PDF、多栏论文、公式、表格最强；
- **UniMERNet** 公式识别（LaTeX 转换开源域领先）；
- **TableMaster** 表格重建（HTML/Markdown 网格，跨行跨列完整）；
- 双 backend：pipeline（快）与 VLM（精，分数更高需单独测）。

**Marker 2（速度选手，2026-07 全重写）**
- 三转换路径：balanced（Surya VLM 处理版面，嵌入文本差时整页重 OCR，GPU 上质量最高）/ fast（rf-detr 版面 + pdftext，最小 VLM）/ --disable_ocr（纯 CPU 文本层）；
- **device-aware 默认**：GPU 走 balanced，CPU/MPS 走 fast；
- 架构突破：多个薄 CPU worker 共享单 Surya 推理服务，父进程预算 VLM 并发，吞吐随服务容量扩展而非单进程 VRAM（balanced ~2.9 pg/s vs 单流 ~0.3 pg/s，10× 差距）；
- 输入格式：PDF、图像、PPTX、DOCX、XLSX、HTML、EPUB；
- 破坏性变更：Python 3.10+，Poetry→uv（pip 命令不变），移除 structured-extraction converter 与 extractors。

**Docling（治理/格式选手）**
- MIT + LF AI & Data Foundation，商用零顾虑；
- **TableFormer** 表格重建（跨行跨列 span 完整）；
- 输入超文档范围：WAV/MP3/EML/MSG/LaTeX/XBRL；
- `DoclingDocument` 层级 JSON，section 节点/段落边界暴露，**结构感知 chunking 最成熟**（按 section header 断块，表格/代码块保持原子）；
- 显式 air-gap（内网隔离）支持。

**Surya（底层引擎，90+ 语言）**
- 多语言 ViT encoder-decoder；行级文本检测、版面分割、阅读顺序、表格识别；
- 公式→KaTeX LaTeX（原 Texify 已并入）；
- Marker 2 的核心组件之一；
- vLLM 加速本地执行。

## 五、混合路由架构（生产推荐）

单一工具很难覆盖所有文档类型，生产 RAG 的标准模式是**混合路由**：

```
PDF 页
  │
  ├─ 数字件（PyMuPDF get_text() 返回 >50 字符）
  │   └─ 布局解析器（Docling / Marker fast / MinerU pipeline）
  │       └─ 保留版面树/阅读顺序，按需 OCR 图像区域
  │
  └─ 扫描件（文本层 <50 字符）
      └─ VLM-OCR（PaddleOCR-VL / DeepSeek-OCR / dots.ocr）
          └─ 整页重读，出 markdown/JSON
```

路由判定极快：`fitz` 的 `get_text()` 返回空串或极短即判为扫描页。

**RAG 接入三阶段**：
1. **抽取**：VLM/管线出 markdown + 版面 JSON；
2. **chunking**：**结构感知**——按 section header（`#`/`##`）断块，表格/代码块保持原子，不要固定 512-token 滑窗（会丢弃结构元数据）；
3. **embedding**：表格作为干净 Markdown/HTML 字符串嵌入，**附加 section 面包屑**（`Document > Financial Results > Q3 Cash Flow`）+ 页码 + 文档标题 + section 路径，让向量库能做混合检索 + 元数据预过滤。

**坑**：朴素 RAG 直接固定滑窗切 markdown，会丢弃现代解析器生成的结构元数据，是 RAG 质量被"归咎于检索器"的真正元凶（garbage in, garbage out）。

## 六、经典流水线（仍有用武之地）

VLM 不是银弹，经典流水线在**离线/零网络/低足印**场景仍有价值：

- **PP-OCRv5**（百度，2025）：轻量，OmniDocBench 1-edit-distance 第一，压过 Qwen2.5-VL-72B 等旗舰 VLM，适合离线/边缘；
- **EasyOCR**：Python 友好的 PyTorch OCR 封装，入门比 PaddleOCR 容易，精度略逊；
- **MMOCR**（OpenMMLab）：研究向 OCR 框架，训练自定义模型；
- **TROCR**（微软）：transformer 系，手写强；
- **Tesseract 5**：512MB RAM 起，简单文本/极小硬件兜底；
- **Florence-2**（微软 770M）：通用视觉，OCR 只是附带能力，100+ 语言；
- **Nougat**（350M）：学术 PDF 专精，LaTeX 强，CC-BY-NC 许可。

**PP-StructureV3**（百度）：86.73% OmniDocBench v1.5，表格结构识别。

### 7.2 截图多模态检索系统的 OCR 层选型

结合《2026-08-23 截图多模态智能检索系统技术调研》的需求（OCR + 人脸 + YOLO + 检索）：

- **OCR 引擎**：**PaddleOCR-VL-1.6 + vLLM**，单卡 L20 或 2080 Ti 都能跑，2GB 显存极轻，100+ 语言覆盖中英，OmniDocBench SOTA，直接出结构化 JSON（`text_blocks` + 坐标）；
- **兜底/离线**：PP-OCRv5 经典流水线，零网络、低足印，VLM 服务不可用时顶上；
- **人脸/YOLO**：保持既有方案，OCR 结果与其坐标框对齐后入库；
- **RAG 入库**：用 Docling（MIT 无顾虑）或 Marker 2 做 PDF 入库，结构感知 chunking + section 面包屑；
- **扫描件兜底**：老扫描件路由到 PaddleOCR-VL 全页 VLM（管线类在老扫描件上只有 43 分，VLM 85+）。

### 7.3 与既有 LLM 推理节点的关系

OCR VLM（0.3-3B）与主力 LLM（Qwen3.8-27B，~17-28GB）**可以同卡共存**：L20 48GB 跑 Qwen3.8-27B-FP8（~28GB）+ PaddleOCR-VL-1.6（~2GB）+ KV 余量，单卡一站式"OCR + 理解 + 检索"。2080 Ti 双卡继续跑 Qwen3.8-27B-MTP-Q4（52 t/s）做轻量推理/备份，OCR 任务按需切到 L20。

## 八、坑与注意事项

1. **基准分数不可直接横比**：OmniDocBench、olmOCR-bench、1-edit-distance 的评测脚手架/文档集/harness 都不同，论文自报分数与第三方复测可能有差距。选型前应在**自己的文档集**上跑 olmOCR-bench harness（开源，带 MinerU/Docling/LiteParse runner）。
2. **管线类集体弱于老扫描件**：olmOCR-bench Old scans 各类管线最高仅 43.2，全页 VLM（Chandra 2 / dots.ocr 1.5）才到 85+。扫描件重的语料必须走 VLM。
3. **Marker fast 模式公式塌方**：arXiv 数学 83.9→23.4（fast 模式从文本层读公式），数学密集文档必须用 balanced 或 VLM 档。
4. **许可红线**：MinerU 超 100M MAU/月收 $20M、Marker 权重超 $5M 营收/融资，都要商业授权。内部工具一般远低于阈值，但开放在线服务前法务过一遍。
5. **DPI 不是越高越好**：150-200 DPI 即可，更高 DPI 增加 token 数但精度增益不线性。
6. **结构感知 chunking 比解析器本身更影响 RAG 质量**：固定滑窗切 markdown 是常见反模式。
7. **VLM 与管线是不同工具，不是替代关系**：Marker 团队明确"我们是管线不是 VLM"，扫描件/数学/极限精度 VLM 档仍全面领先管线。
8. **Turing 卡无 FP8 硬件**：OCR VLM 体量小，FP16/INT8 足够，别为了 FP8 折腾。
9. **olmOCR-bench 数字来自 Datalab 自测**：所有 Marker/MinerU/Docling 对比数字都是 Datalab 在自己硬件上跑的，可复现但反映单一基准的文档混合，自己语料上排名可能不同。
10. **DeepSeek-OCR-2 与 Unlimited-OCR 是不同代际**：OCR-2 是 DeepSeek 二代（Visual Causal Flow），Unlimited-OCR 是百度从 DeepSeek-OCR 继续训练加 Sliding Window Attention 做多页，别混淆。
